
Le compte MariaDB utilisé par l'application (`appphp`) est soumis au principe du moindre privilège. Il ne possède que le droit de lire (`SELECT`) les données de la base `demo`. Il n'a pas les droits d'écriture (`INSERT`, `UPDATE`, `DELETE`) ni les droits de modification de structure (`DROP`, `ALTER`).  
Ainsi, si une faille de type "Injection SQL" est exploitée dans le code PHP, l'attaquant sera limité aux droits de `appphp` et ne pourra ni écrire de données malveillantes, ni détruire la base.  
De plus, on distingue deux types d'erreurs : l'erreur **1698** (refus d'authentification, l'utilisateur OS n'est pas reconnu) et l'erreur **1142** (refus d'autorisation, l'utilisateur est reconnu mais n'a pas les droits pour cette action).

## Ligne de commande VM maintenance

### Tentative d'écriture (INSERT)

vagrant@maintenance-sec:~$ sudo -u appphp mysql demo -e "INSERT INTO messages (content) VALUES ('x');"

-------------
INSERT INTO messages (content) VALUES ('x')

------------

ERROR 1142 (42000) at line 1: INSERT command denied to user 'appphp'@'localhost' for table `demo`.`messages`

### Tentative de suppression (DROP)

vagrant@maintenance-sec:~$ sudo -u appphp mysql demo -e "DROP TABLE messages;"

--------------
DROP TABLE messages

--------------

ERROR 1142 (42000) at line 1: DROP command denied to user 'appphp'@'localhost' for table `demo`.`messages`


Refus d'écriture et de supression (code 1142) : le compte appphp est limité à la lecture seule.

#### Quel GRANT précis justifie ces refus ?

 L'utilisateur ne possède que le `GRANT SELECT` sur la base `demo` (prouvé en Partie 1).
    
#### Comparer le code 1142 et 1698 
1698 est une erreur d'authentification (l'utilisateur `vagrant` n'existe pas). 
1142 est une erreur d'autorisation (l'utilisateur `appphp` existe et est authentifié, mais n'a pas le privilège requis).
#### Une injection SQL permettrait-elle d'écrire ?** 
Non, car le compte utilisé par l'application pour se connecter à la base est bridé en lecture seule, ne injection SQL s'exécuterait avec les droits de `appphp` (SELECT uniquement).
Elle ne pourrait pas écrire ou supprimer des données, le moindre privilège limite l'impact.
