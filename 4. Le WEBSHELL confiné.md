
Le webshell tourne via le service Nginx/PHP-FPM sous l'identité de l'utilisateur système `appphp`. Pour limiter l'impact en cas d'exécution de code non désiré (comme ce webshell), PHP est configuré avec des directives strictes.  
La directive `disable_functions` désactive les fonctions PHP permettant d'exécuter des commandes système (comme `system()` ou `exec()`). La directive `open_basedir` limite l'accès aux fichiers uniquement au répertoire du site web, empêchant la lecture de fichiers critiques du système. Enfin, `security.limit_extensions` s'assure que seuls les fichiers avec l'extension `.php` sont interprétés par le serveur.

### Test du webshell depuis attaquant-CLI1 (htest.php)**

vagrant@attaquant:~$ curl -s http://172.28.128.222/htest.php
disable_functions = exec,passthru,shell_exec,system,proc_open,popen
open_basedir       = /var/www/demo/
function system()  : DESACTIVEE
lecture /etc/passwd: BLOQUEE (open_basedir)

Le webshell est confiné : exécution de commandes et lecture de fichiers système bloquées.
#### Quelle directive empêche  system() /exec()? où est-elle définie?

C'est `disable_functions`, définie dans le fichier principal `/etc/php/8.3/fpm/php.ini`.
#### Quelle directive empêche la lecture de `/etc/passwd` ?**  

C'est `open_basedir`, définie dans la configuration du pool `/etc/php/8.3/fpm/pool.d/appphp.conf`.
#### security.limit_extensions : que limite-t-il?

Il limite l'exécution de code PHP aux fichiers ayant une **extension spécifique** (ici `.php`), empêchant par exemple l'exécution d'un fichier image (`.png`) qui contiendrait du code malveillant.
